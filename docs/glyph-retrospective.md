# Glyph Evaluation & Engineering Retrospective

An engineering retrospective and trade-off analysis of adopting **[Glyph](https://github.com/chadetov/glyph)** (`@glyphlang/glyph`) for building the core domain logic, RBAC permissions, and analytics engine in this web application.

---

## 1. Tooling & Platform Quirks (Early Preview Stage)

- **Binary Execution Permissions**: When installing `@glyphlang/glyph` via npm on macOS, the platform binary in `node_modules/@glyphlang/darwin-arm64/bin/glyph` was missing executable permissions (`chmod +x`), requiring a manual permissions fix before `glyph` could run.
- **CLI Flag Inconsistencies**: The `--no-test` flag mentioned in earlier documentation was rejected by the CLI in favor of `--no-check`.

---

## 2. Standard Library Gaps

- **Missing Standard Math Utilities**: While Glyph ships with `std/result`, `std/option`, `std/array`, `std/string`, `std/io`, `std/json`, etc., it lacks standard mathematical helpers (e.g., `std/math` with `round`, `min`, `max`). Calculations like rounding cycle/lead times had to be handled via arithmetic formulas or delegated to the TypeScript layer.

---

## 3. Build System & Module Resolution Friction

- **Internal Runtime Alias Wiring**: Glyph generates `.glyph-runtime` dependencies with bare imports like `import "std/schema"` and `import "std/result"`. For Vite and root TypeScript to recognize these without compile-time errors, we had to manually configure path aliases in both `tsconfig.json` (`"std/*": ["src/generated/.glyph-runtime/std/*"]`) and `vite.config.ts`.
- **Two-Step Compilation Step**: Unlike pure TypeScript/React projects where Vite handles everything via fast on-the-fly transpilation (esbuild), using Glyph introduces an extra compile step (`glyph build`) before Vite can bundle the app.

---

## 4. Generated Type Narrowing in Strict TypeScript

- **Type Guard Signatures**: The schema validators generated by Glyph emit `.is(value: unknown): boolean` rather than TypeScript type predicates (`(value: unknown): value is T`). Under strict TypeScript checking, calling `this.is(value)` didn't automatically narrow `value` from `unknown` in the emitted `.parse()` methods without relaxing certain root TypeScript flags.

---

## 5. Strict Syntax Ergonomics (Intentional, but Unforgiving)

Glyph is deliberately designed to prevent AI agents from taking shortcuts or creating silent edge cases. While this guarantees verifiability, it requires adjusting to several strict rules:

- **No `if`/`else`**: Every single condition must be written as an exhaustive `match` block with trailing commas on every arm (`true => ..., false => ...,`).
- **No Object Shorthand**: Writing `{ reporterId, title }` causes a syntax error; you must explicitly write `{ reporterId: reporterId, title: title }`.
- **Explicit Mutation Requirement**: Every single state modification or array append must be prefixed with `mut` (`mut total = total + 1`, `mut arr.push(item)`).

---

## Summary Takeaway

| What Worked Great | Where Friction Occurred |
| :--- | :--- |
| Core business logic (RBAC, analytics formulas, status transitions) compiled to clean, deterministic TypeScript. | Initial package install permissions and build configuration setup. |
| Zero runtime crashes from unhandled conditions thanks to exhaustive `match`. | Gaps in utility libraries (like Math) and missing type predicates in generated validators. |
| Seamless import of the compiled modules into standard React components. | Extra build step required before the frontend dev server can start. |
